🧠 Como pensar para implementar CSS
Antes de escrever .btn { color: red }, decida em qual camada o estilo vive

🪜 Pirâmide do CSS aplicado

  • 1. Tokens (:root): cores, espaços, raios. Mudou aqui, mudou tudo.
  • 2. Reset/Base: *, html, body, tipografia padrão.
  • 3. Layout: Grid e Flex para estrutura da página (sem conteúdo).
  • 4. Componentes (BEM): .card, .card__title, .card--featured.
  • 5. Utilities: .text-center, .mt-2. Pequenas, declarativas (estilo Bootstrap/Tailwind).
  • 6. Estado: :hover, .is-active, [aria-expanded].

✅ Heurística do "Onde colocar?"

1. É uma cor/medida usada em 3+ lugares? Vira token.
2. É um padrão de página inteira (header, sidebar, grid)? É layout.
3. É um pedaço reutilizável (card, alerta, badge)? É componente BEM.
4. É um ajuste pontual (margin extra em uma seção)? É utility.

🚫 Cheiros de "CSS espaguete"

  • !important em mais de 2 lugares.
  • Cor hexadecimal repetida em 5 arquivos diferentes.
  • div div div .btn · seletor com peso 4+.
  • Margin que "compensa" margin de outro lugar.

🎯 Quando usar cada técnica

  • Flex: uma dimensão (linha de botões, navbar).
  • Grid: duas dimensões (layout de página, cards).
  • auto-fit + minmax: grid que se quebra sozinho sem media query.
  • clamp(): tipografia fluida sem breakpoints.

📐 Breakpoints "saudáveis"

Não invente: use os mesmos do framework do projeto (Bootstrap: sm 576, md 768, lg 992, xl 1200). Consistência entre páginas vale mais que precisão pixel-perfect.

💲 jQuery · para que ainda serve em 2026?
Quando o projeto não tem framework e você precisa de DOM rápido, jQuery é açúcar sintático sobre document.querySelector
vanilla vs jQuery
// Vanilla JS
const btn = document.querySelector('.btn-mov');
btn.addEventListener('click', () => {
document.querySelectorAll('.card')
.forEach(c => c.classList.toggle('is-open'));
});
// jQuery
$('.btn-mov').on('click', () => {
$('.card').toggleClass('is-open');
});

⚡ Pontos fortes

  • API uniforme: quebra cabeças de cross-browser que ainda existem em projetos legados.
  • Curva curta: 1 caractere ($) faz querySelectorAll + forEach.
  • Animações simples: .fadeIn(), .slideToggle().
  • Ajax compacto: $.ajax, $.get com promises.

⚠️ Limites

  • Não substitui um modelo reativo (Svelte, React, Vue).
  • Manipular muito DOM via jQuery é o mesmo problema do "JS no onclick".
  • Para projetos novos sem legado, prefira ESM + classes.
💲 jQuery · classes, dimensões e propriedades
Três áreas que aparecem o tempo todo: alternar visual (classes), medir tela (dimensões) e ler/setar atributos (props)

🎨 Classes de CSS

Adicionar, remover ou alternar uma classe é o jeito mais limpo de mudar visual: o CSS continua dono do estilo, o JS só liga e desliga estado.

$('.bovino')
.addClass('destacado')
.removeClass('novo');
$('#btn').toggleClass('on');
if ($(el).hasClass('on')) ...

📐 Dimensões

Mede a tela ou um elemento sem se preocupar com offsetWidth, scroll, padding. Útil para reagir ao tamanho.

$(window).width(); // viewport
$(window).height();
$('.card').innerWidth();
$('.card').outerWidth();
$('.card').offset();

🔧 Propriedades e CSS

Diferença prática: .attr() mexe no HTML, .prop() mexe no estado do DOM, .css() aplica estilo direto.

$('#chk').prop('checked', true);
$('img').attr('src', url);
$('.alerta').css({
background: '#fef2f2',
color: '#dc2626' });

🧪 Regra de ouro

Prefira alternar classes a aplicar .css() direto. O CSS controla o visual, o JS controla o estado. Quando precisar medir, use $(window).width() com debounce para evitar disparar 60x por segundo no resize.

✅ Quando usar Bootstrap

  • MVP precisa entregar telas em horas, não dias.
  • Time não tem designer e o produto é operacional.
  • Você precisa de acessibilidade básica "de graça".

⚠️ Quando evitar

  • Identidade visual exige diferenciação forte (todos os sites ficam parecidos).
  • Bundle precisa ser pequeno (importe só o que usar).
  • Já existe um design system próprio com tokens.
⚡ Rethinking Reactivity · por que isso importa hoje
Rich Harris (Svelte) explica: se o framework sabe o que mudou, ele atualiza só aquilo · vDOM ficou pesado para nada

🧬 Três níveis de reatividade

  • Nível 0 · jQuery / DOM direto: você descreve como mudar. Frágil, mas direto.
  • Nível 1 · Virtual DOM (React): re-renderiza tudo e compara. Diff custa CPU.
  • Nível 2 · Signals / Reatividade fina (Svelte 5, Solid): o compilador rastreia a dependência exata. Atualiza só o nó certo.

🎯 O que levar para a prova e para a vida

  • "Reatividade" não é mágica: é quem rastreia qual estado afeta qual pedaço da UI.
  • Quanto mais o compilador sabe, menos JS roda em runtime.
  • Em projetos pequenos (BrPec MVP), vanilla + classes + jQuery entrega bem; em projetos grandes, frameworks compensam o custo de aprendizado.
  • SWEBOK Cap. 11 vai dizer: independente da escolha, verificação contínua (review, teste, lint) é o que sustenta qualidade.
📘 SWEBOK v4 · Cap. 11 · Verification & Quality Practice
Boas práticas de qualidade não são opcionais: são o que diferencia o front "funciona" do front "está pronto"

🔎 Verificação · estamos construindo certo?

  • Inspections / Reviews: code review, checklists, walkthroughs.
  • Static analysis: ESLint, Stylelint, TypeScript, axe (acessibilidade).
  • Dynamic verification: testes unit/integration/E2E rodando em CI.
  • Quality models: ISO/IEC 25010 (Usabilidade, Acessibilidade, Manutenibilidade, Desempenho).

🏗️ Quality Practice no front BrPec

  • Lint: ESLint para o JS, Stylelint para o CSS.
  • Tokens: uma fonte de verdade para tema/cores reduz bug visual.
  • BEM: nome de classe carrega intenção, evita conflito.
  • Acessibilidade: aria-label, contraste mínimo, foco visível.
  • Performance: img loading="lazy", imagens em WebP, sem JS de 200kb.

CRÍTICO Express MVC, AppError e middleware central

Revisar arquitetura de 6 camadas (Aulas 5-6) · asyncHandler envolvendo o controller · classe AppError com status e mensagem · middleware (err, req, res, next) registrado por último · diferença entre res.status().json() e next(err).

CRÍTICO REST · verbos, idempotência, status codes

POST não é idempotente · PUT e DELETE são · 200 OK, 201 Created, 204 No Content, 400 Bad Request, 404 Not Found, 409 Conflict, 422 Unprocessable, 500 Internal · resposta para violação de unicidade.

CRÍTICO ACID e transações com pg

Atomicidade exige BEGIN / COMMIT / ROLLBACK explícito · cada pool.query isolado roda em auto-commit · consistência, isolamento e durabilidade · por que uma sequência de UPDATEs sem transação quebra o invariante de "soma constante".

IMPORTANTE Normalização 1FN, 2FN, 3FN

1FN: atributos atômicos, chave primária · 2FN: dependência total da PK composta · 3FN: nenhuma dependência transitiva entre não-chave · saber decompor uma tabela "feia" e identificar PKs/FKs.

IMPORTANTE Modelo conceitual · Chen ou Crow's Foot

Entidades com atributos e PK · cardinalidade mínima e máxima nos dois lados · entidade associativa para N:N · prática: ler enunciado em texto e desenhar.

IMPORTANTE Engenharia de Requisitos · RF vs RN

RF descreve o que o sistema faz (cadastra, registra, autentica) · RN descreve a restrição/política do negócio (prioridade, ordem FIFO, disponibilidade mínima) · separar bem as duas categorias.

REVISAR Lógica proposicional

Comutatividade de ∧ e ∨ · equivalência P → Q ≡ ¬P ∨ Q · dupla negação ¬(¬P) ≡ P · De Morgan · tabela-verdade de implicações compostas (A ∧ B) → C.

REVISAR Grafos

Definição de dígrafo (arestas direcionadas) · bipartido (dois conjuntos sem arestas internas) · loop (aresta de um vértice nele mesmo) · matriz de adjacência: linha = origem, coluna = destino, 1 se há aresta · ordem alfabética nas colunas.

REVISAR Arquitetura MVC e camadas

Models, Views, Controllers, Services, Repositories, Helpers · cada camada com responsabilidade única · controllers finos, services com regra, repositories tocando o banco · diagrama do fluxo da requisição.

REVISAR TypeScript e tipos

Inferência de tipos com z.infer<typeof schema> · diferença entre interface e type · extends Error para criar classes de exceção · readonly, ? opcional, | união.
